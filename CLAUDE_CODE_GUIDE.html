🎯 Konteks Proyek

Penelitian lokalisasi robot humanoid OP3 (Robotis) menggunakan ROS2 Humble di simulator Webots. Robot bermain sepak bola di lapangan kidsize RoboCup (9m × 6m). Tujuan: robot dapat mengetahui posisinya sendiri di lapangan secara akurat menggunakan kamera dan sensor IMU.

🔴 Known Issues

ISSUE #1 — KRITIS: AMCL Collapse di Area Dekat Gawang

Ketika robot berada di |x| > 2.5m (mendekati gawang), scan laser mendeteksi jaring gawang sebagai obstacle. Peta AMCL tidak mengandung jaring → semua partikel dapat likelihood rendah → particle collapse → AMCL diam.

Upaya yang gagal: scan_gate (v10.7) + parameter AMCL agresif → memperburuk area tengah lapangan. Rollback ke v10.7b tapi masalah near-goal belum solved.

Perlu: Debug live — cek apakah scan_gate memfilter terlalu banyak, apakah goal_localizer publish pose salah.

ISSUE #2: scan_gate + goal_localizer membuat v10.7b lebih buruk dari v10.6

Diagnosis: kemungkinan (a) scan_gate memfilter range yang terlalu besar, menghapus point cloud garis lapangan, atau (b) goal_localizer mendeteksi tiang palsu dan publish pose salah terus-menerus.

Cara debug:

ros2 topic hz /field_scan_gated
ros2 topic echo /field_scan_gated --field ranges | python3 -c "
import sys, ast
for line in sys.stdin:
    r = ast.literal_eval(line.strip())
    valid = [x for x in r if x < 4.5]
    print(f'valid ranges: {len(valid)}/{len(r)}')"
ros2 topic echo /goal_localizer_debug
ros2 node kill /scan_gate && ros2 node kill /goal_localizer  # test tanpa keduanya
ISSUE #3: field_boundary_detector v2.1 belum diverifikasi penuh

Sky-first approach (v2.1) diperbaiki dari v2.0 yang gagal karena jaring gawang. Namun belum ada test komprehensif di semua posisi robot. Verifikasi visual dari /field_boundary_image diperlukan.

ISSUE #4: crossing_amcl_constraint belum dievaluasi kuantitatif

Node aktif dan publish /initialpose, tapi belum ada perbandingan RMSE dengan/tanpa node ini. Jalankan localization_evaluator.py untuk mendapatkan angka.

🔧 Debug Playbook

Quick Sanity Check

# 1. Cek semua node aktif
ros2 node list | grep -E "amcl|ekf|crossing|boundary|segment|scan"

# 2. Cek topic yang kritis aktif
ros2 topic hz /field_line_segments   # harusnya ~10Hz
ros2 topic hz /detected_crossings    # harusnya ~10Hz
ros2 topic hz /field_scan_gated      # harusnya ~10Hz
ros2 topic hz /odometry/filtered     # harusnya ~10Hz

# 3. Cek scan_gate tidak membuang terlalu banyak data
ros2 topic echo /field_scan_gated --once 2>/dev/null | grep -c "inf\|4.5"

Debug Near-Goal Problem (PRIORITAS)

# Step 1: Isolasi apakah scan_gate yang bermasalah
# Disable scan_gate, ubah AMCL kembali ke field_scan_stable
ros2 param set /amcl scan_topic field_scan_stable
ros2 node kill /scan_gate
# Uji: apakah area tengah lapangan kembali normal?

# Step 2: Cek apakah goal_localizer publish pose yang aneh
ros2 topic echo /goal_localizer_debug
ros2 topic echo /initialpose | grep -A5 "position"
# Jika position.x melompat jauh → goal_localizer salah deteksi

# Step 3: Isolasi node per node
ros2 node kill /goal_localizer     # test tanpa goal_localizer
ros2 node kill /scan_gate          # test tanpa scan_gate
ros2 node kill /crossing_amcl_constraint  # test tanpa crossing constraint

# Step 4: Monitor particle count AMCL
ros2 topic echo /particle_cloud --field poses | wc -l
# Jika turun drastis di area dekat gawang → particle collapse

Evaluasi RMSE

# Run evaluator (simpan CSV)
ros2 run soccer_object_localization localization_evaluator \
  --ros-args -p output_csv:=/tmp/eval_$(date +%H%M).csv

# Setelah robot bergerak, analisis hasil
python3 -c "
import csv, math
with open('/tmp/eval_HHMM.csv') as f:
    rows = list(csv.DictReader(f))
errors = [float(r['error_m']) for r in rows if r.get('error_m')]
print(f'N={len(errors)}')
print(f'RMSE = {math.sqrt(sum(e**2 for e in errors)/len(errors)):.3f}m')
print(f'Mean = {sum(errors)/len(errors):.3f}m')
print(f'Max  = {max(errors):.3f}m')
"

💻 Cara Bekerja dengan Claude Code

Kenapa Claude Code lebih baik untuk proyek ini:

Akses langsung ke filesystem → bisa baca semua file sekaligus tanpa upload. Bisa run perintah ROS2 untuk debug live. Iterasi langsung tanpa copy-paste. Bisa monitor topic dan log secara real-time.

Workflow yang Disarankan

  • Baca guide ini dulu

    File ini adalah entry point. Baca semua section sebelum mulai mengubah kode.

  • Baca source file yang relevan

    Jangan ubah kode tanpa membaca isinya terlebih dahulu. Setiap file memiliki docstring yang menjelaskan versi, perubahan, dan alasan perubahan.

    cat ~/basbot/src/soccer_object_localization/soccer_object_localization/scan_gate.py
  • Debug sebelum ubah

    Jalankan perintah debug di bagian Debug Playbook untuk memahami kondisi sistem sebelum membuat perubahan apapun.

  • Ubah satu hal, test, laporkan

    Jangan ubah banyak parameter sekaligus. Satu perubahan per iterasi. Catat hasilnya (lebih baik/buruk/sama).

  • Update docstring setiap perubahan signifikan

    Tambahkan changelog di docstring file Python. Ini penting agar riwayat perubahan tidak hilang.
